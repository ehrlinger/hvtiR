## The design question to settle first

🔴 **Do not hand-write that table into a vignette.** A static table of twelve
version numbers is a staleness generator, and this repo already has the machinery
to avoid it:

- `members()` returns the 11 rows with `package` and `repo`.
- `inst/extdata/catalog.csv` has been the single source of truth for every
  published package list since v1.0.4 (PR #8), and already renders the CV, the
  profile README, the personal site and the LinkedIn checklist.
- `status(remote = TRUE)` already fetches each member's `DESCRIPTION` from GitHub.

So the table should be **generated**, the way `hvtiGraphics`' `function_map.qmd`
generates its coverage table. Decide between:

- **(a) Render at build time** from `catalog.csv` plus a live `status()` call.
  Always current; needs network during pkgdown build, and pkgdown builds in CI.
- **(b) Render from `catalog.csv` alone**, with the docs URL derived per member
  and no version column at all. No network, never stale, less information.
- **(c) Add a `docs_url` column to `catalog.csv`** and render the table from it,
  with versions omitted or fetched only when available.

My recommendation is **(c) plus (b)**: put the URL in the catalog where the rest
of the family metadata already lives, and leave versions off the page entirely.
A reader who wants the version is one click from a site that states it correctly,
and the page can never be wrong. `hazard` is not a `members()` row, so it needs a
deliberate exception either way.

The family map is the opposite case: it changes a few times a year and has no
generated source, so **embed the SVG** and treat it as an authored figure.

## Where things go in this repo

- Design record → `dev/specs/2026-09-02-family-map-design.md`, and add its row to
  `dev/specs/README.md`. That README's table is the index; a new spec that is not
  listed there is invisible.
- The pages themselves → `vignettes/`. There is currently one vignette,
  `hvtiR.qmd`. Adding articles means adding an `articles:` section to
  `_pkgdown.yml`, which has none today — only `reference:`.
- ⚠️ **Nothing of ours goes in `docs/`.** Per `dev/specs/README.md`, pkgdown
  refuses to build into a directory it did not create, and anything of ours there
  breaks the site build.
- Version bump: `tools/check_version.py` is an **unconditional** guard in this
  repo and no other family repo has it. Any merge needs a bump plus the matching
  `NEWS.md` entry, even for a docs-only change.

Logged here because they were found while checking the sites, and each is a
separate work item.

1. 🔴 **`hvtiRtemplates`' pkgdown site is live**, serving v1.0.20. The vault
   records a 2026-08-24 decision that Pages was deliberately left **off** for
   that repo — "leave it off rather than publish internal CORR workflow analysis
   under `specs/artifacts/`" — and `synthesis-2026-08-25` flags its `DESCRIPTION`
   `URL:` as pointing at a deliberate 404. **The site is up.** Either the
   decision was reversed and never written down, or Pages was enabled by
   accident. Worth confirming what is actually published there before the
   meeting, because the original objection was about content, not about links.
2. **`hvtiRbootstrap` is 0.9.2**, not the 0.9.0 the 2026-09-01 session notes
   record as released that day. Two patch versions landed unnarrated.
3. **`hvtiR`'s own `_pkgdown.yml` has no `articles:` section**, so the existing
   `vignettes/hvtiR.qmd` may not be surfaced in the navbar. Check before adding
   more.
